checked on Roblox (every row, until Connor runs the check below).

## Run the check (Windows, one run, about 10 minutes)

`scripts/check-assets.ps1` asks Roblox's public endpoint
`https://economy.roblox.com/v2/assets/<id>/details` about every id in `tools/asset-ids.json`
(the list this file is generated from). It is read-only: it changes no source file and uploads
nothing. It writes `ASSETS-CHECK.md` and `ASSETS-CHECK.csv` next to the repo with, for each id, whether
it loads, the asset type, who owns it (you = Roblox user 5682024709, a group, or someone else, with the
creator id and name), and a short **must fix** list at the top (failing and foreign-owned first, the four
machine meshes before everything else).

Open PowerShell in the repo folder (File Explorer, open the Timberline-Tycoon folder, click the address
bar, type `powershell`, press Enter), then run these one at a time:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\check-assets.ps1
```

Try only the four machine meshes first (a few seconds): `.\scripts\check-assets.ps1 -Only 124635139968707,76460785351208,91355579985009,87960541936824`

Until you run it every status below is `not checked yet`; nothing here has been checked against Roblox.

## Consumers and their fallback

| Consumer | If the asset is slow | If it fails | Bounded wait |
| --- | --- | --- | --- |
| MeshKit.Create (every shop, prop, tree, rock, kit piece, vehicle, axe, NPC) | returns nil at once, part-built art stays, the swap queue dresses it when it lands | part-built art stays for good; first 5 failures warned with the engine's text; 8 misses in a row with none loaded stops asking | none on the world build (never yields); preload join 40 s, stragglers go on alone |
| MeshKit.Attempt (TownMeshes, ShopKit, VehicleMeshes, NPCMeshes, NatureArt, AxeArt, TreeMeshes, KitMeshes, RobuxBoxArt, LogicItems, and since this audit MiningArt) | part-built first, swapped when the mesh lands | stays part-built | none |
| MachineSkin.Prepare from MachineArt (sawmills, planers, chop saw, belts, Sky Bin) | part-built machine for that model | part-built machine | none. **Gap:** not inside Attempt, so a machine built before its meshes load stays part-built until it is rebuilt (see Findings) |
| MiningArt furnace, Prospector (stall and chute), craft bench | part-built, lit, working | part-built | none (fixed in this audit: they were never swapped) |
| ItemMeshes.LoadAsync (plot kit shell) | part-built | part-built | own thread, 20 s preload |
| UIArt skins | flat colour card | flat colour card | ContentProvider.PreloadAsync on its own thread, never on a card build |
| UITheme.HudIcons | short text on the button | short text | none |
| StoreBoard / StoreUI card art | disc colour (letter glyph only when the image id is 0) | blank coloured disc | none |
| SoundData | silent | silent (engine warns) | none |
| WeatherController embers and mist textures | particles without art | same | none |
| MaterialService variants (grass, ground, leafy) | base material colour | base material colour | none |

Skyboxes, Decals, SurfaceAppearance, animations and badge images: none is referenced by id in the
source. LightingController makes a default `Sky` (engine skybox, only star and body settings),
terrain colours are `Terrain:SetMaterialColor`, character and NPC motion is code-driven, WoodFX only
reads SurfaceAppearances that exist, and badge ids are 0. Re-check if that changes.

## Findings (12 October 2026)

1. **Why SmeltingFurnace, Prospector, OreChute and CraftBench stayed part-built.** Their ids are
   correct: every machine piece id matches `assets/uploaded-machines-tld1.json` or
   `assets/uploaded-machines-rocks.json`, and each has a MeshTemplates file. The cause was timing plus a
   missing swap. MiningService builds those four at server start; the `machines` group is last in
   MeshManifest, so its meshes were still queued behind about 500 others. `MiningArt` called
   `MachineSkin.Prepare` outside `MeshKit.Attempt`, so the miss was final (and logged as "did not
   load" although the load was only pending). MiningArt now builds the part-built machine first and
   swaps the mesh in when it lands (`MeshKit.Attempt`), like every other builder.
2. **Same gap remains for plot machines** (sawmills, planers, chop saw, belts, Sky Bin via MachineArt):
   a machine built before its meshes are cached stays part-built until its model is rebuilt (rejoin or
   re-place). MachineSkin now logs `was still loading` instead of `did not load` in that case. A real fix
   needs PlotService to re-dress; not done here (touches plot item registration).
3. **Store card images** (nine `StoreData` image ids: the three older ones on Tow Service, Timber
   Classic and Paint Shop, which may be Decals; six Connor uploaded on 12 October 2026 as IMAGE assets). They
   go through `StoreArt` (rbxthumb asset thumbnail), which renders any image-like id. Whether each shows the
   right picture, and that moderation has cleared it, is not checked: the sandbox cannot reach Roblox.
   `scripts/check-store-icons.ps1` checks the six new ones on Connor's machine.
4. **Old Roblox sound ids** (`SoundData`: 4110925712, 282906960, 1516791621, 1841461968, 1848183670,
   9116970949, 9117181540, 9118187543, 9120549564) are not owned by the game. Since the 2022 audio
   privacy change a sound only plays if it is public Roblox audio or yours. A failure is silent, never a
   crash. The 911x/912x ones are noted in SoundData as public Creator Store audio. Unverified.
5. **57 mesh ids have no MeshTemplates fallback**: 32 plot-kit pieces in `ItemMeshData` (loaded by
   AssetService only) and 25 `Collision` pieces in `TownModels` (never loaded). Not a bug.
6. **19 mesh ids are written twice on purpose** (`BlenderAssets` mirrors `BacklogModels`). Nothing else
   shares an id between modules; no model container id is used as a MeshId.
